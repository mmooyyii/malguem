## malguem

[English](README.en.md)

在Android TV上看 epub / cbz 格式的漫画和小说的app, 让所有的操作都能通过遥控器完成. 界面支持中文/英文 (跟随系统语言).

支持四种数据源: WebDAV / SMB / OPDS 书库 (Komga、Kavita、Calibre-Web 等自建书库) / 本地硬盘.
添加数据源时可以自动扫描局域网里的 alist(5244) / SMB(445) 服务, 不用对着遥控器敲 IP.

### 流式解析: 从不下载整本

epub 和 cbz 本质上都是 zip. 这个 app 不会把书下载下来再打开, 它只用 HTTP Range 去取当前真正要显示的那一点字节:

- **开书通常 1 次往返**. 先读文件尾的 512KB, 一般一口气就同时拿到 EOCD 和整个中央目录, 包里每个文件的偏移与长度当场全有; epub 再解析 opf 拿到阅读顺序、目录和封面.
- **再开同一本书 0 次往返**. 中央目录与 opf 的解析结果落进 SQLite, 下次开书直接从库里恢复, 发出去的第一个请求就是正文本身. 首页那一排封面也是这么来的.
- **一屏的东西合成一条请求**. 不是"一个文件一个请求": 相邻条目的偏移差就是这一条 [本地头 + 压缩数据] 的精确长度, 于是一页正文和它引用的图片/CSS/字体能拼成一条 multi-range 请求, 一次往返全部取回 —— 连"先取本地头定位、再取数据"的第二次往返都省掉了.
- **提前往前挖**. 漫画预取后面 16 页, 小说预取后面 5 章; 一翻页就丢掉还在排队的旧预取, 把带宽让给当前页. 链路延迟高时大批量 range 会拆成 4 条连接并行拉.
- **取回的内容进 LRU 缓存**. 上限取 256MB 与堆的一半里较小的那个, 通宵看也不会把低内存盒子撑爆.

所以打开一本 500MB 的漫画, 落地的流量就是文件尾那 512KB, 翻到哪页才去拉哪页的图.

代价是请求数量多: 如果 WebDAV 后端接的是网盘, **非常频繁**的 Range 请求有可能触发风控, 尽量用本地磁盘或局域网 NAS 做存储.

### 遥控器操作

- 首页最上面一行是**最近阅读**, 点开直接续读
- 文件列表里对着条目按**菜单键或长按OK**: 书=切换漫画/小说, 数据源=编辑/删除, 最近阅读=切换/移除
- 阅读时按 **OK 键**呼出菜单: 目录跳转 / 跳转到页 / 字号与夜间模式(小说) / 阅读方向与单页模式(漫画) / 切换阅读模式
- 首页有**检查更新**按钮, 发现新版本会下载并拉起安装 (不做任何后台自动检查);
  大陆网络连不上 github 时, **长按该按钮**可设置自定义更新源 (指向任意放了 apk 和 version.json 的 http 目录, 比如家里的 alist, 支持 `http://用户名:密码@主机/路径/`)

#### 对于漫画, 会把整个屏幕分成左右2块, 尽量不产生滚动条, 完整地展示整页. 左右键翻页, 看日漫可以在菜单里切成 右→左 的阅读顺序

cbz 就是一个 zip 装着一堆图, 一张图一页, 页序按文件名自然排 (page2 排在 page10 前面), 同样按需取, 不解压整包. 因为没有文字流, cbz 只有漫画模式.
